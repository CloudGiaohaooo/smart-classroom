# 压测报告（登录 / 课程列表）

> 压测对象：优达智慧课堂教学管理平台 后端（Spring Boot 3.2.5 + Java 17，Docker 容器）
> 压测日期：2026-10-17
> 压测工具：`scripts/load-test.mjs`（Node 24 零依赖，内置 http + 连接复用）
> 复现方式：栈启动后执行 `node scripts/load-test.mjs http://localhost:8080 20 1000`

---

## 一、压测环境

| 项目 | 值 |
| --- | --- |
| 运行环境 | Docker Desktop（Windows 11，WSL2 后端），容器 `youda-backend` |
| 后端 | Spring Boot 3.2.5 + MyBatis-Plus + Spring Security + Redis 缓存 |
| 数据库 / 缓存 | MySQL 8.0 / Redis 7（均为同栈容器） |
| 压测发起端 | 本机 Node 24，`keep-alive` 连接复用 |

> 说明：这是**开发机（Docker Desktop）**上的结果，端口映射与虚拟化带来额外网络开销，数值用于「量级判断与横向对比」，不代表生产物理机性能。

---

## 二、压测结果

### 场景 S1 —— 登录接口（顺序 ×100）

`POST /api/auth/login`，合法账号 `teacher/123456`，串行 100 次，测单请求成本与顺序吞吐。

| 指标 | 值 |
| --- | --- |
| 吞吐 QPS | **17.2 req/s**（顺序） |
| 平均延迟 | 58.12 ms |
| P50 | 57 ms |
| P90 | 61 ms |
| P99 | 67 ms |
| 最大 | 68 ms |

> 登录延迟几乎全部由 **BCrypt 密码哈希（默认 cost=10）+ JWT 签发** 贡献，串行下稳定在 ~58ms，无毛刺。这是「安全性换取单次登录耗时」的典型表现。

### 场景 S2 —— 登录接口（并发突发 ×20，验证限流）

同一账号 + 同一 IP 同时发起 20 次登录，验证新增的**登录限流**（`login.rate-limit.max-attempts: 5`，账号 + IP 双维度固定窗口）。

| 结果 | 数量 |
| --- | --- |
| 登录成功（200） | **5** |
| 被限流（业务码 429） | **15** |

> 结论：**限流按设计生效**——窗口内前 5 次放行，第 6 次起返回 429「请求过于频繁」。20 并发下恰好 5 成功 / 15 被拒，与 `max-attempts=5` 完全一致，证明 A6 登录加固真实可用。

### 场景 S3 —— 课程列表（并发 ×1000，带 JWT）

`GET /api/courses?current=1&size=10`，携带有效 JWT，并发 20，共 1000 次，测认证读路径吞吐与尾部延迟。

| 指标 | 值 |
| --- | --- |
| 吞吐 QPS | **49.5 req/s** |
| 平均延迟 | 20.2 ms |
| P50 | 18 ms |
| P90 | 24 ms |
| P99 | 131 ms |
| 最大 | 137 ms |
| 失败数 | 0 |

> 读路径比登录快约 3 倍（P50 18ms vs 57ms），体现「缓存读 + 权限缓存」相对「密码哈希」的优势。P99 出现 131ms 的尾部延迟，主要来自 Docker 端口映射抖动与偶发缓存未命中，属开发环境噪声。

---

## 三、结论

1. **登录是明确瓶颈**：单次 ~58ms，串行 QPS ~17，瓶颈在 BCrypt，这是有意的安全取舍（防离线爆破）。
2. **读路径明显更快**：认证读接口 P50 ~18ms，QPS ~50（并发 20），缓存与权限缓存有效。
3. **登录限流真实可用**：并发 20 → 5 放行 / 15 限流，与阈值配置严格一致。

---

## 四、局限与已知权衡（诚实说明）

1. **开发机数值**：Docker Desktop + WSL2 的端口映射与虚拟化放大了网络延迟，上述数值为下限估计，不代表生产性能。
2. **限流的 IP 维度有误伤风险**：固定窗口按「账号 + 来源 IP」计数，若多个用户位于同一出口 IP（如校园网 NAT / 公司代理），高并发正常登录可能被误限。这是固定窗口限流的固有权衡，改进方向为「滑动窗口 + 每账号独立计数 + 验证码降级」。
3. **只测了同步路径**：未压测文件上传（大文件 IO）与批阅（事务写）等重接口，后续可补。
4. **并发规模有限**：最大并发 20，未做「QPS 随并发增长」的饱和曲线（压测脚本支持 `node scripts/load-test.mjs <url> <并发> <请求数>` 自行扩参）。
