# 真实运行数据采集步骤

> 目的：把「演示数据」替换为「真实班级一周使用产生的数据」，用于（1）支撑学习预警看板的真实性、（2）补充雷同评测里缺失的「同主题独立写作」负例、（3）答辩时提供可追溯的真实运行证据。
>
> **诚实边界（重要）**：本文件只提供**采集工具与步骤**。真实数据必须由你找同学/班级**真实运行**产生，**不得伪造**——伪造的「真实」数据违背评审本意，且一被追问时间线/账号/内容细节就会穿帮。下面的每一步都不涉及编造数据。

---

## 一、前置条件

1. 系统已可用：`docker compose up -d --build` 后 4 容器 healthy，前端 `http://localhost` 可访问。
2. 找一个小范围真实用户（同班同学、学弟学妹，10~30 人即可），约定跑 5~7 天。
3. 保留当前演示数据作对照，**新采集放到独立环境**（见下文「隔离」），避免污染。

---

## 二、采集运行（让真实用户用起来）

1. **建真实课程与作业**：用教师账号 `teacher` 在系统里新建 1~2 门真实课程、布置 2~3 次真实作业（如「提交实验报告」「提交读书笔记」）。
2. **邀请真实用户**：给每位同学建账号（`sys_user` 表，角色 STUDENT），并把 TA 拉进课程（`course_enrollment` 选课）。
3. **让 TA 正常使用一周**：
   - 登录（产生 `student_behavior` 的 `LOGIN` 事件）；
   - 下载/查看课程资源（产生 `VIEW_RESOURCE`）；
   - 提交作业（产生 `SUBMIT_ASSIGNMENT` + `submission` 记录）。
4. 一周后，数据自然沉淀在 `sys_user / course / course_enrollment / assignment / submission / student_behavior / course_resource` 表中。

> 这样得到的才是「真实行为数据」：有真实时间戳、真实提交内容、真实活跃/沉默分布，预警看板才有说服力。

---

## 三、导出

```bash
# 在项目根目录执行（依赖 youda-mysql 容器在跑）
bash scripts/export-real-data.sh data/real-20261024
```

脚本会把 7 张表导出为 `*.sql` 到指定目录（`mysqldump --complete-insert`，含列名与完整 INSERT）。

> 目录 `data/` 已在 `.gitignore` 中，真实数据**不会进入公开仓库**。

---

## 四、脱敏（提交/分享前必做）

真实数据含姓名、学号、邮箱等敏感信息，**入库或写进报告前必须先脱敏**：

| 字段 | 处理方式 |
| --- | --- |
| `sys_user.real_name` | 替换为 `学生01` / `学生02` 等占位 |
| `sys_user.username` | 保留（仅用于登录，通常非敏感）或替换为 `stu01` |
| `sys_user.phone / email` | 置空或替换为假值 |
| `submission.content` | 若含真实姓名/学号，删除或替换 |

脱敏后再用于答辩演示与报告配图，避免隐私泄露（与 `答辩材料-原版备份/` 的隔离原则一致）。

---

## 五、替换演示数据

两种方式，按需选其一：

**方式 A（推荐，干净）**：开一个全新环境导入真实数据。
1. 新建数据库 `youda_classroom_real`；
2. `docker exec -i youda-mysql mysql -uyouda -p<pwd> youda_classroom_real < data/real-xxx/ 下的各表 sql`（先导 sys_user/course，再导 enrollment/assignment/submission/behavior）；
3. 改 `application.yml` 或环境变量 `SPRING_DATASOURCE_URL` 指向新库。

**方式 B（同库替换）**：停用演示初始化器，再导入。
1. 将 `DataInitializer`、`BehaviorDemoDataInitializer` 的 `@Component` 改为仅在演示 profile 下启用（如加 `@Profile("demo")`）；
2. 删除演示数据（`DELETE FROM student_behavior; DELETE FROM submission; ...`）；
3. 导入脱敏后的真实数据。

> 无论哪种方式，都**保留演示初始化器**，以便答辩时随时回退到「5 簇 × 4 人」的可控演示场景。

---

## 六、用真实数据重跑评测

真实数据能补上 C1 评测的短板——「同主题独立写作」负例：

1. 从真实 `submission` 里挑出**同一作业下、内容确实不同但主题相同**的提交对，标为 `distinct`（人工确认）；
2. 挑出**内容高度相似**的提交对，标为 `duplicate`；
3. 追加到 `docs/evaluation/雷同标注集.json`（或另建 `雷同标注集-真实.json`）；
4. 重跑 `mvn test -Dtest=SimilarityEvaluationTest`，看真实负例如何影响 0.45 阈值的精确率，并据此调整阈值。
