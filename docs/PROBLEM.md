# 问题定义（Problem Statement）

> 用途：把项目从「又一个教学管理系统」重新表述为「**三个可评估的工程问题**」，为考研复试提供「有主张、有证据、有边界」的话术骨架。
>
> **诚实定位（务必守住）**：本项目是「教学管理平台 + 工程/安全加固」的实践，**不是**学术意义上的「智慧教室 / 多模态课堂行为分析」。下面三个「问题」是**工程实现层面的可评估问题**，它们的价值在于「问题定义清晰 + 指标可量化 + 边界诚实」，而**不在于**「提出新的算法或理论」。答辩时请据此表述，不夸大。

---

## 总问题

> 在**轻量、离线、不依赖大模型/云服务**的约束下，如何让一个教学管理平台在「作业批阅、学习预警、资源存储」三个环节上，**降低教师的机械重复劳动、让教学状态更可见**，并且每一个改进都能被**量化评估**？

它拆成三个子问题：

---

## 问题 1：如何低成本发现作业雷同、减少评语重复劳动？

- **痛点**：教师面对大量文本提交，人工逐篇比对「改几个字就交」的抄袭效率极低；相似质量的作业反复写相同评语是纯机械劳动。
- **为什么值得做**：雷同检测与评语推荐是批阅环节的「高频 + 低价值」劳动，用算法辅助教师初筛，能把教师精力还给「判断与反馈」本身。
- **可量化指标**：雷同检测的**精确率 / 召回率 / F1**；评语推荐的命中条数。
- **当前证据**：100 对「构造即真值」标注集上，阈值 0.45 → P/R/F1 = 1.0/1.0/1.0，0.75 → 1.0/0.625/0.769（见 `docs/EVALUATION.md`）。
- **边界**：字符级方法对「换说法」召回有限；定位是「辅助初筛」，最终判定由教师确认。

## 问题 2：如何让教师及时看到「谁没交作业、谁很久没登录」，又不侵入业务代码？

- **痛点**：传统埋点要在每个业务方法里手写 `insert` 日志代码，侵入性强、易漏、难维护。
- **为什么值得做**：预警的本质是「把沉默的学生捞出来」，让教师从「被动等学生来问」变成「主动关注异常」。
- **可量化指标**：预警**触发准确率**（真实活跃/沉默分布下的命中情况）、埋点对业务主链路的**延迟影响**（→ 0，异步）。
- **当前证据**：`@BehaviorLog` 声明式埋点 + 外置规则；登录 `demo18` 后「长期未登录」预警实时消失，证明埋点→聚合→预警链路正确。
- **边界**：规则阈值、非预测模型；真实数据采集是待办（不伪造）。

## 问题 3：如何避免同一课件被反复上传浪费磁盘？

- **痛点**：同一份课件（PPT/PDF）被不同教师、不同课程反复上传，本地为同一内容存多份副本。
- **为什么值得做**：内容去重是「存储成本」与「内容寻址」的经典工程问题，小到单机目录、大到对象存储通用。
- **可量化指标**：重复上传的**磁盘节省**（物理文件数 vs 元数据记录数）、去重**命中率**。
- **当前证据**：同文件二次上传返回 `deduplicated=true`、物理文件仅一份；引用计数删除正确（`FileMd5Test` 对照 RFC 1321）。
- **边界**：MD5 用于去重非防篡改；跨实例去重需对象存储。

## 贯穿三个问题的工程主线

除三个子问题外，项目还有一条「工程规范 + 安全加固」的主线，用统一的证据支撑：

| 主张 | 证据 |
| --- | --- |
| 安全不是事后补丁 | BCrypt / JWT / RBAC + 归属校验 / 上传白名单 / 签名 URL 下载 / 登录限流 / CORS 白名单（见 `项目技术详解文档.md` 第六节） |
| 越权可被防御 | `CourseOwnershipGuard` + 学生选课门禁，MockMvc 测试固化（P0 横向越权已封死） |
| 可观测可排障 | traceId 日志链路（`X-Trace-Id`）+ 统一异常 + SpringDoc |
| 可复现 | `docker compose up -d --build` 一键起 4 服务 + 种子数据 + 演示账号 + 复现脚本 |

---

## 评估框架与伦理边界

- **框架**：问题 → 指标 → 基线 → 评估 → 限制（详见 `docs/EVALUATION.md`）。
- **伦理**：埋点最小化采集、脱敏、预警不自动处罚、学生知情、学生文本不出服务器（详见 `docs/LIMITATIONS.md` 第六节）。

> **给复试的一句总起**：「我没有做很重的算法，而是挑了两个教学场景里真实存在、又能被量化评估的工程问题——批阅的雷同与评语、预警的埋点与可见性——在离线的约束下给出可复现的解法，并诚实记录每条边界。相比堆功能，我更在意『每个主张都有证据』。」
