# 评估总览（Evaluation）

> 用途：把项目里「**每一个主张，都配一条可追溯的证据**」集中到一个入口。导师看方法论证据，面试官看结果证据。
> 完整原始报告见 `docs/evaluation/` 目录；本文档只做「主张—证据」索引与结论，不重复原始数据。
>
> **诚实边界**：所有数字都来自**真实可复现的实验**（见各报告「复现方式」），没有任何一项是编造或估算；同时，每一项都如实标注了**局限**——小样本就是小样本、合成数据就是合成数据。

## 评估框架

本项目的评估采用「**问题 → 指标 → 基线 → 评估 → 限制**」五段式，把「三个工程小尝试」从「功能清单」升级为「可评估的工程问题」：

| 环节 | 要回答的问题 |
| --- | --- |
| 问题 | 这个功能到底在解决什么痛点？ |
| 指标 | 用什么指标衡量「解决得好不好」？ |
| 基线 | 和谁比？（规则阈值 vs 无基线、合成标注集等） |
| 评估 | 实际测得多少？ |
| 限制 | 结果在什么条件下成立、什么条件下不成立？ |

## 1. 智能辅助批阅（雷同检测 + 评语推荐）

**主张**：TF-IDF + 余弦相似度能在离线、无大模型约束下，有效区分「近逐字 / 轻改写」的雷同提交与「跨主题」的独立提交。

**指标**：精确率 P、召回率 R、F1（在 100 对「构造即真值」的标注集上）。

**证据**（来源 `docs/evaluation/雷同检测评测报告.md`，复现：`cd backend && mvn test -Dtest=SimilarityEvaluationTest`）：

| 阈值 | 判定含义 | TP | FP | FN | TN | 精确率 | 召回率 | F1 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0.45 | 进入「相似提交」列表 | 40 | 0 | 0 | 60 | 1.000 | 1.000 | 1.000 |
| 0.75 | 标记「疑似雷同」 | 25 | 0 | 15 | 60 | 1.000 | 0.625 | 0.769 |

- 两个阈值是**分层设计**：0.45 偏敏感（把可疑的都捞进来供人工复核），0.75 偏精确（只标高置信雷同、避免误伤）。
- 真雷同最低分 0.464 与非雷同最高分 0.190 完全分离，安全区间约 [0.20, 0.45]。

**限制（如实）**：负例全取「跨主题」文本、区分度天然偏高，导致 0.45 的精确率呈理想值 1.0；真实难点「同主题但独立写作」未被覆盖。字符 n-gram 对「换说法」召回有限。详见报告第五节。

## 2. 学习预警看板（AOP 埋点 + 阈值规则）

**主张**：`@BehaviorLog` 声明式埋点 + 外置阈值规则，能以「零侵入、不拖慢业务」的方式给教师一个「谁很久没登录、谁没交作业」的预警视图。

**指标定义（参与度）**：预警目前用**离散行为事件**而非连续参与度打分，规则为：
- 「长期未登录」：超过 `login-inactive-days = 7` 天无 `LOGIN` 事件；
- 「长期未提交」：超过 `no-submit-days = 7` 天无 `SUBMIT_ASSIGNMENT` 事件；
- 看板展示近 `trend-days = 7` 天提交率趋势 + 资源访问热力 TopN。

**证据**：登录演示学生 `demo18` 后，其「长期未登录」预警**实时消失**，证明 AOP 切面实时写入 + 预警规则联调正确（`docs/screenshots/02-dashboard-warning.png`）。

**基线（如实）**：**无 ML 基线对比**。当前是规则阈值，不是预测模型；「规则 vs 逻辑回归」的对比是待补项，需要真实数据（见第 5 节）。这是有意的取舍——没有数据时硬上 ML 只会得到无评估的黑盒。

**限制**：预警是「事后看板」而非「实时推送」；埋点只覆盖登录/看资源/交作业三类事件，粒度较粗。

## 3. 课程资源 MD5 秒传去重

**主张**：同一物理文件重复上传时只落盘一次、复用物理文件，节省磁盘；删除按引用计数防误删。

**证据**（实测，`mvn test` 的 `FileMd5Test` 对照 RFC 1321 标准向量校验算法正确性；`ResourceControllerTest` 覆盖秒传路径）：
- 同一文件连续上传两次，第二次返回 `deduplicated=true`、`fileUrl/fileMd5` 一致，物理文件仅一份；
- 引用计数删除：先删有引用记录 → 文件保留；删最后一条 → 文件清理。

**限制**：MD5 用于去重而非防篡改；跨实例去重需配合对象存储/内容寻址，当前单机目录内有效。

## 4. 性能（压测）

**主张**：读路径依赖缓存与权限缓存明显快于登录路径；登录限流按设计生效。

**证据**（来源 `docs/evaluation/压测报告.md`，复现：`node scripts/load-test.mjs http://localhost:8080 20 1000`）：

| 场景 | 吞吐 / 结果 |
| --- | --- |
| S1 登录（顺序 ×100） | QPS **17.2**，P50 **57ms** / P99 **67ms**（瓶颈在 BCrypt，有意的安全取舍） |
| S2 登录限流（并发 ×20） | **5 成功 / 15 被限流**（与 `max-attempts=5` 严格一致） |
| S3 课程列表（并发 ×1000） | QPS **49.5**，P50 **18ms** / P99 **131ms**，失败 0 |

**限制（如实）**：开发机（Docker Desktop + WSL2）数值，为下限估计；只测了同步读/登录路径，未压测文件上传与批阅事务写；并发规模有限（最大 20）。

## 6. 运行数据：模拟演示数据（已提供） + 真实采集（可选）

这里把「运行数据」拆成两条明确分开的轨道，**二者不能混为一谈**：

### 6.1 模拟演示数据（已提供，程序生成）

`SimulatedDataInitializer`（`demo.simulated.enabled=true` 时启用）用**固定种子的随机数**生成一个更接近真实班级的模拟数据集：

- 40 名模拟学生（sim01~sim40，密码 123456，可登录）+ 每人 1~3 门选课；
- 提交完成率按活跃度分档（活跃约 90% / 一般约 65% / 沉默约 20%），得分近似 N(82,9) 截断到 [55,100]；
- 近 14 天行为埋点，活跃（约 55%）/ 一般（约 30%）/ 沉默（约 15%）三档分布，沉默档近 7 天无登录，可触发「长期未登录」预警。

> **用途与边界**：这只用于让预警看板 / 提交率趋势 / 资源热力在答辩现场呈现真实感的**分布**。
> 它是<b>模拟数据</b>，不是「真实运行数据」——答辩时须明确说「演示数据为程序模拟生成」，不得描述成真实采集结果。

### 6.2 真实采集（可选，需真实用户）

**状态：未完成，需用户出面真实采集**——工具与步骤已备好（`docs/evaluation/真实数据采集步骤.md` + `scripts/export-real-data.sh`）。

要补的是两类证据，均**不能伪造**：
1. **真实行为数据**（10~30 人真实跑 5~7 天）：支撑预警看板的「真实活跃/沉默分布」；
2. **真实提交对标注**：补上雷同评测缺失的「同主题独立写作」负例，重跑 P/R 并据此调阈值。

> 为什么必须真实？伪造的「真实数据」一被追问时间线/账号/内容细节就会穿帮，且违背评审本意。这是本项目的**最后一块诚实边界**。
