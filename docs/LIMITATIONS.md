# 已知局限与反思（Limitations）

> 用途：主动、集中地列出项目的**边界与不足**，每条附**为什么是当前这个样子**与**下一步方向**。
> 导师视角加分点：敢写「局限性」三字，比堆功能清单更能体现「知道自己不知道」。本文档与 `docs/EVALUATION.md` 互补——评估给「证据」，本文给「边界」。

---

## 一、架构层面

| 局限 | 说明 | 改进方向 |
| --- | --- | --- |
| 单体应用 | 前后端分离但后端是单进程单体，未做微服务 | 无必要强行拆微服务；更务实的下一步是**异步化 + 可观测**（见下） |
| 无消息队列 / 分布式事务 | 批阅结果不异步通知、跨库操作依赖单库事务 | 批阅结果用 MQ 异步通知学生（埋点已异步，可复刻同模式） |
| 本地磁盘存储 | 文件存单机目录，无法横向扩展 | 换 MinIO/OSS，存储层已隔离在 `ResourceService` |
| 预警非实时 | 「事后看板」而非「实时推送 / 预测」 | WebSocket 把预警升级为实时告警 |

## 二、数据与评估层面

| 局限 | 说明 | 改进方向 |
| --- | --- | --- |
| 无真实用户规模 | 演示数据由 `DataInitializer` 等构造，缺真实班级一周使用量验证 | 可用 `SimulatedDataInitializer` 生成模拟数据补「真实感分布」；真实采集见 `docs/evaluation/真实数据采集步骤.md`（需真实运行，不伪造） |
| 雷同标注集为合成数据 | 负例偏简单（跨主题），0.45 阈值精确率呈理想值 1.0，未覆盖「同主题独立写作」 | 用真实提交对补充负例，重跑 P/R 调阈值 |
| 学情预警无 ML 基线 | 规则阈值，未与「逻辑回归 / 阈值模型」做基线对比 | 有真实数据后再补基线对比；当前诚实标注「规则、无预测」 |
| 压测数值为下限 | 开发机（Docker Desktop + WSL2）结果，非生产物理机性能 | 生产环境重跑；补文件上传/批阅事务写路径压测 |

## 三、安全层面（已知权衡）

| 局限 | 说明 | 改进方向 |
| --- | --- | --- |
| 固定窗口限流误伤 | 按来源 IP 计数，校园网 NAT / 公司代理下同出口用户可能被误限 | 滑动窗口 + 每账号独立计数 + 验证码降级 |
| 签名 URL 外泄窗口 | 下载签名 URL 有效期（默认 1800s）内可被他人下载 | 缩短 TTL、按用户绑定签名、记录下载审计 |
| MD5 仅用于去重 | 去重指纹，非防篡改；对主动碰撞攻击不安全 | 防篡改用 SHA-256 + 签名（已由下载签名 HMAC-SHA256 承担） |
| JWT 无状态登出难 | 无状态令牌签出后「立即全局失效」需要额外黑名单机制 | 已做「禁用账号 token 即时失效」；「登出黑名单」按需求再评估 |

## 四、算法层面

- **字符 n-gram 的语义短板**：对「语义等价但用词完全不同的改写」召回有限，这是字符级方法的本质边界（雷同评测报告已如实暴露）。提升需引入词级分词或句向量，但要在「离线 / 无大模型 / 学生文本不出服务器」的约束内权衡。
- **评语推荐是频率统计**：基于历史评语词频，不是生成式，无法对「全新问题」给出建议评语——定位是「减少重复劳动」，不是「替代教师判断」。

## 五、工程质量层面

| 局限 | 说明 | 改进方向 |
| --- | --- | --- |
| 覆盖率数字暂缺 | JaCoCo exec 采集在本机 Windows+中文路径下失败（标准 CI/Linux 不受影响） | 在 CI（Linux）上采集并回填覆盖率徽章 |
| 未系统化压测重接口 | 只压了登录/课程读路径 | 补文件上传（大文件 IO）、批阅（事务写） |

## 六、伦理与隐私边界

项目涉及学生行为数据，明确以下边界（也是网络空间安全专业的加分表达）：

1. **最小化采集**：埋点只记录「登录 / 看资源 / 交作业」三类事件与时间戳，不采集键盘、鼠标轨迹等细粒度行为。
2. **脱敏**：真实数据入库/写报告前必须脱敏（姓名/学号/邮箱替换或置空），见 `真实数据采集步骤.md` 第四节。
3. **预警只做教师参考，不自动处罚**：预警是「提示教师关注」的看板，不直接触发任何对学生的自动处分，把最终判断留给教师。
4. **学生知情边界**：真实采集前需向参与同学说明「在采集哪些行为、用于什么、如何脱敏」——这是数据伦理的底线，也是答辩时「安全与隐私意识」的具体体现。
5. **学生文本不出服务器**：雷同检测完全离线（纯 Java），不调用云端大模型，杜绝学生作业内容外泄风险。

---

## 一句话总结

本项目的边界可概括为：**单体 + 规则 + 合成数据 + 开发机压测**。它们不是「没做完」，而是「在诚实前提下、当前约束下的合理取舍」；每一条都有明确的下一步与可复现的验证方式。把局限说清楚，比把项目说成无所不能更有说服力。
