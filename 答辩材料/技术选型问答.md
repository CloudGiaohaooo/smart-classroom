## 1. 为什么把拦截器换成 Spring Security 过滤链？RBAC 到底解决什么？

**问题**：原来用 `HandlerInterceptor` 鉴权，为什么改？

**答案要点**：
- **执行时机不同**：拦截器在 `DispatcherServlet` 之后（MVC 层），只能做「是否登录」的粗粒度判断；Spring Security 过滤链在进入 MVC **之前**就完成认证，能拿到完整请求上下文。
- **细粒度授权**：配合 `@EnableMethodSecurity` + `@PreAuthorize`，实现方法级授权（如「只有 TEACHER 才能 `submission:grade`」），这是拦截器做不到或很难做到的。
- **RBAC 模型**：四张表（角色 / 权限 / 用户-角色 / 角色-权限）把「谁能干什么」从代码里抽到数据里，权限变更改表即可、无需改代码，且权限从 RBAC 表**实时加载**（改权限无需重新登录/重发 token）。
- **保留兼容**：JWT 载体与 `ThreadLocal` 上下文保持不变，业务代码零改动。

**可延伸**：过滤器 vs 拦截器 vs AOP 的执行顺序；`OncePerRequestFilter` 保证单次执行；`SecurityContextHolder` 的 ThreadLocal 清理。

## 2. Redis 缓存三策略：穿透 / 击穿 / 雪崩怎么防？

**问题**：三个问题分别是什么、你用了什么方案？

**答案要点**（对应 `RedisCacheService`）：
- **缓存穿透**（查一个不存在的数据，每次都打到 DB）：**空值缓存**——把「不存在」也缓存一个短 TTL 的 NULL 标记，下次直接命中空值不再打 DB。
- **缓存击穿**（热点 key 过期瞬间，大量并发同时打到 DB）：**互斥锁重建**——用 `SETNX` 抢锁，只有一个线程去查 DB 重建缓存，其余线程等待/降级。
- **缓存雪崩**（大量 key 同一时刻过期，DB 瞬时被打爆）：**随机 TTL 抖动**——给每个 key 的过期时间加一个随机偏移，避免同时过期。
- **降级兜底**：所有 Redis 操作 `try/catch`，Redis 宕机时自动直查数据库，接口不 500（实测验证）。

**可延伸**：`SETNX` 的锁释放 / 锁过期、布隆过滤器（穿透的另一种解法）、缓存与 DB 双写一致性。

## 3. 雷同检测为什么用 TF-IDF + 余弦，而不是大模型 / 分词库？

**问题**：做「智能」批阅，为什么不上大模型？

**答案要点**：
- **任务本质**：短文本相似度是「两段提交有多像」，TF-IDF + 余弦是经典且够用的解法，不需要生成式大模型。
- **中文分词**：不引入 jieba/hanlp 等词典分词（重依赖），改用**字符 unigram + bigram 滑窗**，无需词典即可覆盖中文，对短文本足够有效。
- **工程约束**：零重依赖、完全离线、无需联网下载权重；学生文本不出服务器，**无隐私外泄风险**（对比调用云端大模型）。
- **IDF 平滑**：用 `log(1 + N/df)` 避免 df=N 时权重归零。

**可延伸**：TF-IDF 的公式、余弦 vs 编辑距离 vs Jaccard；如果要更强的语义相似度可以再叠加 Word2Vec/BERT，但那是「锦上添花」。

## 4. 学习预警为什么用 AOP 埋点，而不是在业务代码里写日志？

**问题**：埋点为什么用切面？

**答案要点**：
- **解耦**：业务方法只加 `@BehaviorLog` 一行注解，埋点逻辑集中在 `BehaviorLogAspect`，业务代码不感知埋点、不污染主流程。
- **一致性**：所有事件统一落库到 `student_behavior`，避免各处手写 `insert` 导致的字段不一致 / 漏埋。
- **旁路容错**：切面 `try/catch` 兜底，埋点失败只告警、绝不打断业务（`@AfterReturning` 只在正常返回后执行，异常登录不记录）。
- **可扩展**：新增一种行为类型只需加一个枚举值 + 注解，不改切面主体。

**可延伸**：`@AfterReturning` vs `@Around` vs `@Before`；切面与事务的代理顺序。

## 5. JWT 无状态 vs Session 会话？为什么选 JWT？

**答案要点**：
- JWT 无状态、服务端不存会话，天然适配前后端分离 + 多实例横向扩展；Session 需要共享存储（Redis）才能跨实例。
- 载荷里只放 userId/username/role，**不放敏感信息**；密钥长度 ≥ 32 字节（HS256）。
- 配合 `ThreadLocal` 上下文让业务代码无感读取当前用户，请求结束 `finally` 清理防泄漏。

**可延伸**：JWT 过期刷新（refresh token）、黑名单登出、为什么说 JWT「注销」是无状态的一个短板。

## 6. MyBatis-Plus 选型理由？和 JPA / MyBatis 比？

**答案要点**：
- MyBatis-Plus 在 MyBatis 基础上提供 `BaseMapper` 通用 CRUD + `LambdaQueryWrapper` 类型安全查询，减少样板代码；
- 复杂多表 JOIN 仍手写 `@Select`，SQL 可控、可优化，比 JPA 的抽象更贴近 SQL；
- 分页用 `Page` + 自定义 SQL 联表，演示 LEFT JOIN 与聚合子查询。

**可延伸**：`map-underscore-to-camel-case` 驼峰映射、逻辑删除、乐观锁插件。
