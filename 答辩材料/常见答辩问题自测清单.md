# 常见答辩问题自测清单

> 本文件是**自检工具，不是背稿材料**：只给「问题」和「你要能答出的要点 / 可能被追问的方向」，**不给标准答案**。答辩前逐条自测，能在 1~2 分钟内用**自己的话**讲清即为通过；讲不清就回到代码/文档里补。
> 使用原则：先结论、再要点、必要时举项目里的具体例子（某个接口、某条 SQL、某段配置）。

---

## 一、项目 / 技术类

### Q1：请简单介绍一下你做的这个项目？
**自查要点**：一句话定位（教学管理平台 + 工程/安全加固）、四大模块（课程/作业/提交/批阅/资源）、技术栈（前端 Vue3、后端 Spring Boot、数据库 MySQL、认证 JWT）、诚实说明「智慧 = 三个工程小尝试」而非研究创新点。
**追问点**：为什么叫「智慧」？和普通教学管理系统区别在哪？

### Q2：为什么采用前后端分离？
**自查要点**：职责分离、可并行开发、可独立部署、便于未来接入移动端；RESTful + JSON 解耦。
**追问点**：前后端分离带来什么问题？（跨域、鉴权、SEO、部署复杂度）

### Q3：什么是 RESTful？你的接口怎么体现的？
**自查要点**：以资源为中心；URL 表示资源、HTTP 方法表示操作、统一返回体。能举出至少一个真实接口路径。
**追问点**：POST 和 PUT 区别？你的接口是严格 RESTful 吗（有哪些不 REST 的地方）？

### Q4：为什么统一封装返回结果 + 全局异常处理？
**自查要点**：前端统一处理、不泄露堆栈/敏感信息、集中处理参数/业务/系统异常。能说清 `@RestControllerAdvice` 的分层。
**追问点**：哪些异常返回什么状态码？业务异常和系统异常怎么区分？

### Q5：JWT 是什么？你的认证流程？
**自查要点**：头部/载荷/签名三部分；登录签发 → 前端存 → 每次请求带 `Authorization` → `JwtAuthenticationFilter` 校验 → ThreadLocal + SecurityContext 授权；无状态。
**追问点**：JWT 缺点？（登出难、续期难、泄露风险）密钥怎么管理？为什么用 HS256？

### Q6：为什么密码用 BCrypt？
**自查要点**：单向哈希、自带盐、成本可调、抵抗彩虹表；每次加密结果不同。
**追问点**：加盐的意义？BCrypt 和 MD5/SHA-256 用于口令存储的区别？

### Q7：文件上传怎么实现？怎么防安全问题？秒传去重怎么做？
**自查要点**：MultipartFile 接收、落盘、元数据入库；安全 = UUID 重命名、分目录、扩展名白名单、大小限制、签名 URL 下载；秒传 = MD5 计算 → 命中复用物理文件 → 引用计数删除。
**追问点**：为什么 MD5 只用于去重不能用于防篡改？并发上传同一文件怎么办（Redis 锁）？扩展名白名单为什么能防存储型 XSS？

### Q8：前端路由守卫和菜单权限怎么做？
**自查要点**：`meta.roles` 标记、菜单按角色过滤（前端显隐）；后端 `@PreAuthorize` + 归属校验（最终兜底）。
**追问点**：前端隐藏就安全了吗？为什么后端还要校验？

## 二、数据库 / 事务类（复试重点）

### Q9：项目里有哪些多表查询？怎么写？
**自查要点**：课程列表 LEFT JOIN 教师姓名、作业列表聚合子查询统计提交/批阅数、提交记录四表 JOIN。能说出一条 SQL 的字段与 join 条件。
**追问点**：聚合子查询为什么不用多次查询？分页怎么做的？

### Q10：LEFT JOIN 和 INNER JOIN 的区别？
**自查要点**：INNER 只取交集；LEFT 保留左表全行、右表无匹配填 NULL。举课程列表为什么用 LEFT。
**追问点**：LEFT JOIN 右表无匹配的字段怎么处理（NULL 判断）？

### Q11：事务的四大特性 ACID？
**自查要点**：原子性/一致性/隔离性/持久性；用 `@Transactional` 保证批阅原子性。
**追问点**：`@Transactional` 什么时候失效（自调用、非 public 方法、异常被 catch 吞掉）？

### Q12：事务隔离级别？MySQL 默认是什么？
**自查要点**：四种级别 + 各自解决什么问题；InnoDB 默认 REPEATABLE READ，靠 MVCC + 间隙锁防幻读。
**追问点**：可重复读为什么在 MySQL 还能防幻读？MVCC 原理（隐藏列 + undo log）？

### Q13：脏读 / 不可重复读 / 幻读？
**自查要点**：三者的区别（读到未提交数据 / 同一条两次读不一致 / 结果行数变化）。能各举一例。
**追问点**：幻读和不可重复读的本质区别（单行 vs 集合）？

### Q14：索引是什么？项目里怎么用索引？
**自查要点**：B+ 树、空间换时间；用户名唯一索引、外键字段普通索引。
**追问点**：索引为什么快？为什么不是越多越好？最左前缀原则？什么情况索引失效？

### Q15：主键索引和唯一索引的区别？
**自查要点**：主键 = 唯一 + 非空 + 每表一个；唯一索引可多个、可 NULL（因库而异）。
**追问点**：InnoDB 主键为什么建议自增？（页分裂、聚簇索引）

## 三、实习综合类

### Q16：哪些是实习期间做的，哪些是实习后补强的？
**自查要点**：如实区分——实习做了 ER 图、课程/作业列表前端（约 1800 行）、资源上传/批阅接口、测试与文档；实习后主动补强了 JWT/加密/RBAC/看板/工程化。**不夸大、不把补强部分说成实习产出。**
**追问点**：为什么实习结束后还继续做？补强部分怎么证明是你独立完成的？

### Q17：你在实习中具体做了哪些工作？
**自查要点**：完整流程（需求 → ER → 前端 → 后端 → 测试 → 文档）；能说清「自己独立做」vs「协助」的分工。
**追问点**：哪个模块是你 100% 独立完成的？遇到的最大困难是什么、怎么解决的？

### Q18：通过实习你有哪些收获？
**自查要点**：知识（多表/事务/RESTful/Git）、能力（独立开发/排错）、素质（严谨/责任心/协作）。
**追问点**：举一个「排错」的真实案例，说明排查思路。

### Q19：你觉得还有什么不足？
**自查要点**：单体应用、高并发/分布式经验不足、自动化/性能测试接触少。
**追问点**：这些不足你打算怎么补？有没有已经开始行动的证据（如正在写的压测/评测）？

### Q20：为什么选网络空间安全方向 / 项目和专业的结合点？
**自查要点**：安全贯穿开发——BCrypt、JWT、上传防穿越、越权防护、登录限流、签名 URL、CORS 白名单；体会「安全不能是事后补丁」。
**追问点**：说出一个你做的安全设计里「若被攻破」的假设场景，以及对应防御。

### Q21：如果优化这个项目，你会怎么做？
**自查要点**：已做的（RBAC、Redis 三策略、三工程尝试）；想做的（对象存储 MinIO、消息队列、WebSocket 推送、Elasticsearch 检索）。
**追问点**：为什么选这些？优先级怎么排？每一项能说清「解决什么 + 大致方案」即可。
