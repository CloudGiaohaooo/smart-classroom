# 项目演示讲解稿（现场演示用）

> 使用说明：以下脚本按「现场实际运行系统」的顺序编写，每步对应一个页面操作。
> 演示前请确保：后端已启动（8080）、前端已启动（5173）、演示数据已初始化。
> 建议总时长控制在 **4~5 分钟**，边演示边讲解。

---

## 开场（30 秒）

「各位老师好，下面我现场演示一下我在实习期间参与开发的『优达智慧课堂教学管理平台』。先说明定位：这是一个前后端分离的教学管理系统，覆盖课程、作业、批阅、资源四大模块；我主打的不是『智慧』二字的噱头，而是工程规范和安全加固两条主线——所谓智慧能力，只是雷同检测、学习预警、秒传去重这三个工程小尝试。现在系统已经启动，我先从登录开始。」

## 第一步：登录（30 秒）

1. 打开 `http://localhost:5173`，进入登录页。
2. 用教师账号登录：`teacher` / `123456`。
3. 讲解：「登录成功后，后端会签发一个 JWT 令牌，前端把它存到 localStorage，之后每次请求都带上这个令牌做身份认证。」

> 现场演示加分点：打开浏览器开发者工具 Network 面板，展示请求头里的 `Authorization: Bearer ...`，再展示后端返回的 token。

## 第二步：数据概览（20 秒）

1. 登录后进入「数据概览」页。
2. 讲解：「这里展示了课程、教师、学生、作业、待批阅、资源等统计，下面柱状图是按课程统计的作业数量，这些数据是后端用聚合查询实时统计出来的。」

## 第三步：课程管理（40 秒）

1. 点击「课程管理」。
2. 讲解：「这是课程列表，支持分页和关键词搜索。可以看到每门课程都联表显示了授课教师姓名。」
3. 演示新增：点「新增课程」→ 填课程名、选教师 → 保存 → 列表刷新。
4. 讲解：「新增课程走的是 POST 接口，参数在进入 Service 层前就完成了校验。」

## 第四步：作业列表 + 学生提交（1 分钟）

1. 点击「作业列表」。
2. 讲解：「作业列表按课程筛选，每行还统计了提交数和已批阅数，这是用一条 SQL 里的聚合子查询算出来的。」
3. 演示布置作业：点「布置作业」→ 选课程、填标题、设截止时间 → 保存。
4. 讲解：「接下来切换学生视角看提交流程。」→ 右上角退出，用 `student` / `123456` 登录。
5. 点「作业列表」→ 对某作业点「提交作业」→ 填内容 → 提交。
6. 讲解：「学生提交后会记录提交时间，超过截止时间系统会拒绝提交。」

## 第五步：教师批阅反馈（1 分钟）

1. 退出学生账号，重新用 `teacher` 登录。
2. 点击「作业批阅」。
3. 讲解：「这里是教师视角的提交记录列表，联表展示了作业标题、课程名和学生姓名，可以按作业和批阅状态筛选。」
4. 点某条「待批阅」记录 → 打分、填反馈 → 提交批阅。
5. 讲解：「批阅操作在事务里完成，得分、反馈、状态、时间四个字段要么全部成功、要么全部回滚，保证数据一致。」

## 第六步：课程资源上传（40 秒）

1. 点击「课程资源」。
2. 点「上传资源」→ 选课程、选类型、选文件 → 上传。
3. 讲解：「文件上传后会按课程分目录存储，用 UUID 重命名避免覆盖，元数据写入数据库，可以直接点击下载。」

## 第七步：收尾（20 秒）

1. 切回学生账号，点「我的提交」，展示学生能看到的得分和教师反馈。
2. 讲解：「这样就从学生提交到教师批阅再到学生查看反馈，形成完整闭环。以上就是系统的核心功能演示，谢谢各位老师。」

---

## 演示注意事项

1. **提前演练**：至少完整跑一遍，熟悉每个按钮位置，避免现场翻车。
2. **准备离线截图**：万一现场网络/数据库出问题，直接切到 PPT 里的截图页继续讲。
3. **突出技术点**：演示时反复强调 JWT、事务、多表查询、文件上传这几个亮点，引导老师往你准备过的方向提问。
4. **语速适中**：每讲一个功能就停一下，给老师留出打断提问的余地。
5. **主动说局限**：讲完亮点后主动补一句「这是工程小尝试，阈值是经验值、还没做真实验证」，把老师可能挑的刺自己先挑出来，反而显得诚实、可追问。
