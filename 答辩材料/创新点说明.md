## 工程尝试 A：智能辅助批阅（雷同检测 + 评语推荐）

### 问题
传统作业批阅中，教师面对大量文本提交时有两个痛点：
1. **雷同难发现**：学生互相抄袭、改几个字就交，人工逐篇比对效率极低、易漏判；
2. **评语重复劳动**：对相似质量的作业，教师反复写「思路正确，注意边界条件」这类评语，纯属机械重复。

### 方案
在**不引入大模型 / 不联网下载权重**的约束下，用纯 Java 实现轻量 NLP：

- **相似度计算**（`TextSimilarity`）：中文「字符 unigram + bigram」滑窗分词（无需词典），对同一作业下的全部提交构建语料，计算 TF-IDF 向量与余弦相似度。阈值通过 `application.yml` 的 `similarity.*` 外置可调。
- **雷同检测**：批阅页调 `/api/submissions/{id}/grading-assist`，返回 TopN 相似提交（相似度、`疑似雷同` 标记、内容摘要）。
- **评语推荐**：对历史已批阅评语做频率统计（同作业优先、全局兜底），返回 Top3 高频评语，前端「一键填入」。
- **不影响主链路**：评分/反馈仍走原 `@Transactional` 的 `/grade` 接口，辅助接口是纯读旁路，新增能力不改原接口语义。

### 效果
- 实测同簇提交相似度 **86.9% ~ 94.3%**，全部命中「疑似雷同」；跨簇文本被阈值过滤。
- 评语推荐命中 3 条高频评语（各 count=3、均分 85），一键填入减少重复劳动。
- 20 条「5 簇 × 4 人」模拟提交可直观演示聚类效果（截图占位：批阅弹窗内「相似提交提示 + 推荐评语」）。

### 局限
- 阈值 0.45 / 0.75 是经验值，尚未基于人工标注集做精确率/召回率评估（评测见 `docs/evaluation/雷同检测评测报告.md`）。
- 短文本 + 无词典分词，对「语义等价但用词完全不同的改写」召回有限。
- 非学术级 NLP，不涉及语义理解 / 大模型；定位是「辅助教师初筛」，最终判定由教师确认。

### 为什么这个方案够用（可能被追问）
短文本雷同检测本质是「两段文本有多像」，TF-IDF 衡量词重要性、余弦衡量方向一致性，二者组合已能较好区分「改词抄袭」与「原创」；且完全离线，学生文本不出服务器，无隐私外泄风险（对比调用云端大模型）。

## 工程尝试 B：学习预警看板（AOP 零侵入埋点）

### 问题
教师需要一个「谁最近没交作业、谁很久没登录」的预警视图，但传统做法是**在业务代码里到处塞埋点**（登录、看资源、交作业各写一段 `insert` 日志代码），侵入性强、易漏、难维护。

### 方案
- **声明式埋点**：定义 `@BehaviorLog(BehaviorType.XXX)` 注解，业务方法只加一行注解，埋点逻辑统一由 `BehaviorLogAspect` 切面（`@AfterReturning`）处理，**与业务代码完全解耦**。
- **数据模型**：新增 `student_behavior` 表（`student_id / behavior_type / target_id / occur_time`），覆盖登录 / 看资源 / 交作业三类事件。
- **预警规则外置**：`application.yml` 的 `warning.*` 配置「超过 N 天未登录 / 未提交」阈值，服务层按阈值计算预警列表。
- **看板**：教师端 ECharts 三个区块——提交率趋势（折线）、资源访问热力（柱状）、预警学生列表。

### 效果
- 看板返回近 7 天提交趋势、3 门课程资源热度、3 名静默 30 天学生预警，**数据与 DB 一致**。
- 登录演示学生 demo18 后，其「长期未登录」预警**实时消失**，证明切面实时写入与预警规则联调正确（截图占位：登录前后预警列表对比）。
- 埋点为旁路能力，`try/catch` 兜底，任何埋点异常**绝不打断业务主流程**。

### 局限
- 预警是「规则阈值 + 事后看板」，非实时推送、非机器学习预测；演示数据由初始化脚本构造。
- 埋点只覆盖登录 / 看资源 / 交作业三类事件，粒度较粗。

## 工程尝试 C：课程资源 MD5 秒传去重

### 问题
同一份课件（PPT/PDF）常被不同老师、不同课程反复上传，本地磁盘会为同一内容存多份副本，浪费存储空间。

### 方案
1. 上传时用纯 JDK `MessageDigest` 计算文件 MD5（32 位十六进制），随元数据写入 `course_resource.file_md5` 列；
2. 命中相同 MD5 时**复用既有物理文件、仅新增一条元数据记录**（秒传），未命中才落盘；
3. 删除时按 `file_url` 做引用计数，多条记录共享同一物理文件时保留文件、不误删；
4. 开关 `resource.dedup-enabled` 外置到 `application.yml`，上传结果通过新增响应字段 `ResourceUploadVO`（`resourceId / fileMd5 / deduplicated / fileUrl`）返回，原接口路径与语义不变。

### 效果
- 连续两次上传同一文件，第二次返回 `deduplicated=true`、提示「秒传成功」，物理文件只存一份（截图占位：上传提示 + `uploads` 目录仅一个文件）。
- `mvn test` 9 测试全绿，`FileMd5Test` 对照 RFC 1321 标准向量校验算法正确性。

### 局限
- MD5 用于内容去重而非防篡改；跨实例去重需配合对象存储/内容寻址，当前单机目录内有效。
- 引用计数基于同一 file_md5 的元数据条数，跨课程复用已考虑（同一物理文件可被多课程引用）。

### 为什么这个方案够用（可能被追问）
- MD5 用于「内容去重」而非密码学防篡改，128 位 + 单机教学场景下碰撞概率可忽略；若需抗主动碰撞攻击可换 SHA-256。
- 秒传去重与「文件是否被篡改」是两件事：这里只解决存储去重，防篡改可用 SHA-256 + 签名另行实现。

## 工程深度（答辩可展开，但不算「创新点」）

1. **RBAC + Spring Security**：四表权限模型（`sys_role / sys_permission / sys_user_role / sys_role_permission`），`@PreAuthorize` 方法级授权替换原拦截器；实测学生调建课/批阅 403、教师批阅 200、未登录 401。
2. **Redis 缓存三策略**：空值缓存（防穿透）/ 互斥锁重建（防击穿）/ 随机 TTL（防雪崩），Redis 宕机自动降级直查 DB，接口不 500。
3. **可观测与质量**：`@RestControllerAdvice` 统一异常、SpringDoc Swagger、JUnit + JaCoCo、Docker Compose 一键部署。
