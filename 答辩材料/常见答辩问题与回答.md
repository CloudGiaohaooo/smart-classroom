# 常见答辩问题与回答

> 分三部分：**项目/技术类**（实习答辩与复试都会问）、**数据库/事务类**（复试重点）、**实习综合类**（实习答辩重点）。
> 回答原则：先结论、再要点、必要时举项目中的具体例子，控制在 1~2 分钟内。

---

## 一、项目 / 技术类

### Q1：请简单介绍一下你做的这个项目？
**答**：这是我在【实习单位】实习期间参与的「优达智慧课堂」教学管理平台，前后端分离架构。我主要完成了四个模块：课程管理、作业列表、作业批阅反馈、课程资源上传。前端用 Vue3 + Element Plus，后端用 Spring Boot + MyBatis-Plus，数据库 MySQL，认证用 JWT。它解决的是教学场景里作业发布、提交、批阅、资源分发流程线上化的问题。

### Q2：为什么采用前后端分离？
**答**：前后端分离让前端专注页面交互、后端专注业务与数据，职责清晰、可并行开发、可独立部署，也方便未来接入移动端。通过 RESTful 接口 + JSON 通信，前后端解耦。

### Q3：什么是 RESTful？你的接口是怎么体现的？
**答**：RESTful 是一种以资源为中心的接口设计风格。我体现在：用 URL 表示资源（如 `/api/courses/{id}`），用 HTTP 方法表达操作（GET 查、POST 增、PUT 改、DELETE 删），返回统一的结构化结果（统一的 `Result` 响应体和状态码）。

### Q4：你为什么要统一封装返回结果和全局异常处理？
**答**：一是让前端能用统一的方式处理成功和失败；二是避免把堆栈信息等敏感内容直接暴露给前端；三是集中处理参数校验异常、业务异常、系统异常，代码更简洁、可维护。我用 `@RestControllerAdvice` 做了全局兜底。

### Q5：JWT 是什么？你的认证流程是怎样的？
**答**：JWT 是无状态的令牌，由头部、载荷、签名三部分组成。流程是：登录成功后服务器签发一个带用户 id、角色和过期时间的 token，前端存起来，之后每次请求放在 `Authorization: Bearer token` 头里，后端 Spring Security 过滤链的 `JwtAuthenticationFilter` 解析校验，通过后把用户信息放进 ThreadLocal 供业务使用，并把 RBAC 权限编码写入 SecurityContext 做方法级授权。它是无状态的，服务端不存 session，适合前后端分离和横向扩展。

### Q6：为什么密码要用 BCrypt？
**答**：BCrypt 是单向哈希算法，自带盐值且计算成本可调，即使数据库泄露也无法还原明文；每次加密结果都不同，能抵抗彩虹表攻击。我使用的是 Spring Security 提供的 `BCryptPasswordEncoder`。

### Q7：你的文件上传是怎么实现的？怎么避免安全问题？
**答**：前端用 FormData 上传，后端用 `MultipartFile` 接收，把文件落盘到本地目录，同时把元数据（文件名、大小、路径）写入数据库。安全上：用 UUID 重命名避免重名覆盖和路径穿越，按课程分目录，限制上传大小，访问路径通过静态资源映射统一暴露。

### Q8：前端路由守卫和菜单权限是怎么做的？
**答**：路由配置里加了 `meta.roles` 字段标记哪些页面只有教师可见，侧边栏菜单根据当前登录用户的角色动态过滤；后端在服务层做最终权限校验兜底。这样前端控制显隐、后端保证安全。

## 二、数据库 / 事务类（复试重点）

### Q9：你的项目里有哪些多表查询？怎么写的？
**答**：课程列表要联表查出教师姓名（course LEFT JOIN sys_user）；作业列表要联表查课程名，同时用聚合子查询统计提交数和已批阅数；提交记录要四表 JOIN 查出作业标题、课程名和学生姓名。我用 MyBatis-Plus 的 `@Select` 注解写自定义 SQL，配合分页插件完成分页。

### Q10：LEFT JOIN 和 INNER JOIN 的区别？
**答**：INNER JOIN 只返回两表都有匹配的行；LEFT JOIN 返回左表全部行，右表没有匹配时用 NULL 填充。我的课程列表用 LEFT JOIN，是为了保证即使教师信息异常，课程也不会丢。

### Q11：谈谈事务的四大特性（ACID）？
**答**：原子性（要么全做要么全不做）、一致性（事务前后数据都满足约束）、隔离性（并发事务互不干扰）、持久性（提交后数据永久保存）。我用 `@Transactional` 保证批阅操作的原子性。

### Q12：什么是事务隔离级别？MySQL 默认是什么？
**答**：隔离级别有未提交读、提交读、可重复读、串行化四个，主要解决脏读、不可重复读、幻读。MySQL InnoDB 默认是可重复读（REPEATABLE READ），通过 MVCC 和间隙锁，在默认级别下也能避免幻读。Spring 里可以通过 `@Transactional(isolation = ...)` 指定。

### Q13：什么是脏读、不可重复读、幻读？
**答**：脏读是读到别人未提交的数据；不可重复读是同一事务两次读同一条数据结果不一致（被别人改或删）；幻读是两次查询结果行数不一致（别人插入或删除了记录）。可重复读能避免脏读和不可重复读，MySQL 下也能避免幻读。

### Q14：索引是什么？你的项目里怎么用索引？
**答**：索引是加速查询的数据结构（B+ 树），本质是用空间换时间。我在用户名的唯一索引上加速登录，在 course_id、teacher_id、assignment_id、student_id 这些外键关联字段上建普通索引，加速联表查询。同时注意索引不是越多越好，写操作会维护索引带来开销。

### Q15：主键索引和唯一索引有什么区别？
**答**：主键索引就是唯一索引的一种，且不允许 NULL，一张表只能有一个；唯一索引允许多个，也允许 NULL（不同数据库略有差异）。它们都能保证列值唯一并加速查询。

## 三、实习综合类

### Q16：这个项目里哪些是实习期间做的，哪些是实习后自己做的？
**答**：实习期间我做的是与实习总结对应的部分——数据库 ER 图设计、课程管理和作业列表两个前端页面（约 1800 行）、协助开发资源上传和作业批阅反馈两个后端接口、Postman 测试与文档撰写。实习结束后，因为我是网络空间安全专业，对系统的安全设计和工程规范比较感兴趣，就主动延伸补强了 JWT 登录认证、密码加密、角色权限控制、数据统计仪表盘，以及统一响应、异常处理、分页、多表联查优化这些工程化内容。整个过程是持续学习的过程，我也如实区分了这两部分。

### Q17：你在实习中具体做了哪些工作？
**答**：我参与了完整开发流程：参加需求评审、协助梳理功能清单并画数据库 ER 图；用 Vue 独立完成课程管理和作业列表页面，约 1800 行代码；用 Spring Boot 协助开发资源上传和作业批阅接口，并用 Postman 做接口测试；写了 30 多条测试用例，跟踪 15 个 Bug 并协助修复 8 个；还撰写了接口文档和用户操作手册。

### Q17：你在实习中遇到的最大困难是什么？怎么解决的？
**答**：最大困难是刚开始对多表联查和事务不熟练。作业列表需要同时统计提交数和已批阅数，我一开始写的是多次查询，性能不好；后来改成在一条 SQL 里用 LEFT JOIN + 聚合子查询完成，性能明显提升。遇到事务问题时，我理解了批阅必须放在事务里保证原子性，避免出现分数改了但状态没改的中间态。

### Q18：通过实习你有哪些收获？
**答**：知识上掌握了多表查询、事务隔离、RESTful 设计和 Git/Linux 基本操作；能力上经历了完整开发周期，初步能独立承担模块开发，学会了定位和排查问题；素质上养成了严谨的编码习惯和责任心，也体会到团队协作和持续学习的重要性。

### Q19：你觉得实习中还有什么不足？
**答**：一是接触的主要是单体应用，对高并发、分布式、微服务等生产级场景经验不足；二是测试方面偏功能测试，对自动化测试和性能测试接触较少。这些也是我接下来要补强的方向。

### Q20：（复试常问）你为什么选择网络空间安全方向 / 这个项目和专业有什么结合点？
**答**：虽然岗位是软件开发，但我的专业是网络空间安全。项目里我特别关注了安全设计：密码用 BCrypt 加密、用 JWT 做无状态认证、上传文件做了防覆盖和路径穿越处理、避免敏感信息泄露。这让我体会到「安全要贯穿开发的每个环节」，也坚定了我继续深入安全方向的决心。

### Q21：如果让你优化这个项目，你会怎么做？
**答**：我已经完成了一部分——引入了 Spring Security + RBAC 四表权限模型、Redis 缓存三策略（穿透/击穿/雪崩）、SpringDoc 接口文档和 JUnit 单测，还加了两块智能能力（TF-IDF 雷同检测 + AOP 学习预警看板）。接下来想做的是：一是把本地文件存储换成 MinIO 对象存储并做 MD5 秒传去重；二是用消息队列做批阅结果异步通知；三是用 WebSocket 把学习预警从「主动看」升级为「实时推送」；四是引入 Elasticsearch 做课程资源全文检索。
